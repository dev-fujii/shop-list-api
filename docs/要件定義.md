# 要件定義

2026-10-16 時点。2026-10-17 に「使う人」と「入力のしかた」を見直した。値や範囲は、作りながら調整する。

## 目的

- 家計簿アプリで記録するとき、わざわざアプリを開いて、分類を選び、金額を入力するのが毎回面倒。
- 入力を「金額と店名」だけにして、分類は自動で決まるようにし、記録の手間を減らす。
- 自動で入力されるようにしたい。Apple Pay で払ったときは自動で記録し、現金などは手で入力できるようにする。

## 使う人

- 複数の人がアカウントを作って使える。データは人ごとに分ける。
- ログイン（アカウント作成を含む）は2段目で作る。それまでは、仮のユーザー1人として動かす。

## 作る範囲

- 作るのはバックエンド（Web API）だけ。画面は作らない。
- 手元では、開発用のツール（`.http` ファイルなど）から API を呼んで確かめる。
- 自動の入力は、iPhone のショートカットの「取引」オートメーションで、Apple Pay で払ったときに金額と店名を API に送る（ショートカットは作品の範囲外）。
- 手で入力するときも、自動のときと同じ取引の登録 API を使う。

## できること

### アカウント（2段目）

- アカウント作成・ログインができる。
- 将来は Google でもログインできるようにする。

### 取引

- 支出と収入（給料など）を記録できる。
- 金額と店名だけで登録できる。日付は省略すると今日になる。
- 送る項目の名前は、金額が `amount`、店名が `merchant`。
- 取引の一覧・1件の取得・更新・削除ができる。
- 削除した取引は完全に消える。

### 分類

- 分類の一覧・登録・更新・削除ができる。
- 分類と分類ルールは、人ごとに持つ。
- 最初から次の分類を、人ごとに用意する: 食費・日用品・交通費・趣味・固定費・給料・未分類。後から増やす・直す・消すことができる。
- その分類の取引が残っているときは、分類を消さずに、残っている件数を返す（「先に取引を移して」と伝えるため。ダイアログを出すのは呼ぶ側）。

### 自動分類

- 登録したとき、店名と分類ルールから分類を自動で決める。どのルールにも当たらなければ「未分類」にする。
- 分類ルールの一覧・登録・更新・削除ができる。
- 取引の分類を手で直したら、次から同じ店はその分類になる（優先度: 中）。

### 集計

- 月ごとの、分類別の合計
- 月の支出の合計
- 収入 − 支出の残り
- 好きな期間（開始日〜終了日）での合計

## 守ること

- 金額は円だけ。1円単位の整数で扱う。
- 金額は1円以上、1,000万円未満。
- 店名は必須。50文字まで。
- 日付は未来の日付も受け付ける（予定の支払いを入れられるように）。
- 上の値は、後から変えられるようにする。
- 入力が正しくないときは、何が違うかを返す。
- 自分のデータしか見たり変えたりできない。

## やらないこと（手元版 11-05 の時点）

- 画面（フロントエンド）
- ログイン（認証）。2段目で足す。
- 明細ファイル（CSV）の取り込み
- 円以外のお金、小数の金額

## 優先度

- 間に合わなければ後に回す: 手で直した分類を次から覚える機能
