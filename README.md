# shop-list-api（家計の記録 API）

家計簿をスマホで毎回手で付けるのが面倒だったので、自動で記録できるように作った Web API です。
金額と店名を送るだけで取引を登録でき、分類（食費・交通費など）は自分で決めたルールをもとに決まります。月や期間を指定して、分類別の合計や収支も取得できます。

今の状態（2026-11-02）

- 下の「できること」はすべて実装し、Azure に公開して動作を確認しました。
- 自動テストは33件で、手元と GitHub Actions の両方で成功しています。
- iPhone のショートカットを手動で実行して、登録できることは確認しました。Apple Pay で支払ったときに自動で送られるかは、まだ確認中です。

## 作った理由

家計簿アプリでの記録は続けていますが、支払いのたびにアプリを開き、分類を選んで、金額を入力するのが面倒でした。

金額と店名を送るだけで分類が自動で決まれば、記録の手間はほとんどなくなると考えました。家計簿アプリはすでに多くありますが、自分で作ることで次の2つを自由に決められます。

- 分類のしかた。「店名にこの言葉が入っていたらこの分類」というルールを自分で作れます。取引の分類を手で直すと、次からは同じ店がその分類になります。
- 見せ方。画面は作らず API だけにしたので、見やすさは後から調整できます。

## 記録の流れ

```text
Apple Pay で払う
  → iPhone のショートカット（「取引」のオートメーション）が金額と店名を送る
  → API が分類ルールで分類を決めて保存する

現金などのとき
  → 同じ API に、手で金額と店名を送る
```

自動の記録も手入力の記録も同じ API を使い、どちらから来たかは `source`（`auto` / `manual`）で区別しています。ショートカット自体は、このリポジトリには含めていません。

## できること

| 機能 | URL | 内容 |
| --- | --- | --- |
| 取引 | `/transactions` | 支出と収入の記録。金額と店名だけで登録でき、日付を省くと今日になる。一覧（分類・期間で絞り込み、ページ分割）・1件の取得・更新・削除 |
| 自動分類 | （取引の登録時） | 店名に含まれるキーワードで分類を決める。どのルールにも当たらなければ未分類（`null`） |
| 分類を手で直したときのルール作成 | （取引の更新時） | 分類を手で変えると、店名をキーワードにしたルールを作る |
| 分類 | `/categories` | 一覧・1件の取得・登録・更新・削除 |
| 分類ルール | `/category-rules` | 「店名のキーワード → 分類」の一覧（ページ分割）・1件の取得・登録・更新・削除。ルールを変えても、過去の取引の分類は変わらない |
| 集計 | `/summaries` | `?month=2026-10` か `?from=...&to=...` で、分類別の合計・支出と収入の合計・収支を返す。期間の最初と最後の日も含み、未分類も集計する |
| 初期分類の投入 | （起動時の引数） | 「食費・日用品・交通費・趣味・固定費・給料」のうち、足りないものだけを追加する |

送るもの・返すもの・エラーの形は [docs/設計.md](docs/設計.md) にあります。

## 使っている技術

| 技術 | 選んだ理由 |
| --- | --- |
| C# / .NET 10 | 今の仕事（ゲーム開発）で C# を使っているので、サーバー側でも使えるようになりたかった |
| ASP.NET Core（コントローラー） | 業務ではコントローラーで書かれていることが多いと思ったから |
| Entity Framework Core | .NET で DB を扱うときの標準的な方法だから |
| PostgreSQL | Azure 以外のクラウドにも移せるから。手元では Docker で動かしている |
| Docker | 使ったことがなかったので覚えたかった。手元で動いたイメージを、そのまま Azure でも動かしている |
| GitHub Container Registry（GHCR） | イメージの置き場所。ソースと同じ GitHub に無料で置ける |
| GitHub Actions | push のたびにビルドとテストを実行して、壊したときにすぐ気付けるようにしたかった |
| Azure Container Apps | 無料枠に収まるから。App Service の無料プランには1日の使用時間に上限があるが、Container Apps は呼ばれないときにコンテナを0個にできる |
| Azure Database for PostgreSQL | 手元と同じ PostgreSQL 17 が使え、12か月の無料枠がある |

## Azure での構成

```text
iPhone のショートカットなど
  → HTTPS
  → Azure Container Apps（API が X-Api-Key の鍵を確かめる）
  → Azure Database for PostgreSQL（Flexible Server。SSL で接続）

イメージ: GHCR の公開イメージを、Container Apps が取得する
```

- DB の接続文字列や鍵は Container Apps のシークレットに入れ、コードや git には入れていません。
- 鍵の無いリクエストには 401 を返します。鍵の設定を入れ忘れたまま公開しないよう、設定が無いと起動しないようにしました（`ValidateOnStart`）。
- 料金がかからないよう、呼ばれないときはコンテナを0個にしています。その代わり、止まっている状態からの最初の1回は、応答まで30秒ほどかかります。
- 公開している URL は載せていません。だれでも呼べる状態にすると、無料枠を使い切られるおそれがあるからです。

無料に収めるための設定などの詳細は [docs/Azure.md](docs/Azure.md) にあります。

## 設計で考えたところ

細かい内容は [docs/設計.md](docs/設計.md) にあります。ここには、特に自分で考えたところだけを書きます。

### 分類の決め方

店名にキーワードがそのまま含まれていれば、一致とみなします（大文字・小文字は区別します）。2つ以上のルールが一致したら、キーワードが長いほうを使います。たとえば「セブン」と「セブンイレブン」なら、より細かく一致する「セブンイレブン」を使います。同じ長さなら id が小さいほうを使います。

### 分類を手で直したら、次から自動にする

分類を別のものに変えたときだけ、店名をそのままキーワードにしてルールを作ります。同じキーワードのルールがすでにあれば、増やさずに分類を書き換えます。金額や日付だけを変えたときと、未分類に戻したときは、ルールを変えません。

取引とルールは一緒に保存し、片方だけが保存された状態にならないようにしました。

### 「未分類」は分類として作らない

どのルールにも当たらない取引は、分類を空（`null`）にしています。「未分類」という分類を作ると、それだけは消せないようにする処理が必要になります。それなら最初から持たないほうがシンプルだと考えました。

### 後から変えそうな値は設定ファイルに出す

1ページの件数や、集計で何も指定しなかったときの月数（今は3か月）など、使いながら変えたくなりそうな値は `appsettings.json` に置きました。金額の上限や文字数のように DB の形に関わる値は、コードの定数にしています。

### ログインを後から足しやすくしておく

今はすべてのリクエストを1人の仮ユーザーとして扱っています。ログインは後から足す予定なので、今のユーザーを返す部分（`CurrentUser`）を仮の形で用意し、差し替えやすくしています。

## テスト

自動テストは全部で33件です。

- DB を使わないもの14件: 分類の決め方と、集計の期間の計算
- 実際の PostgreSQL を使うもの19件: 手で直したときのルール作成、保存の直前に分類が消された場合、初期分類、集計

GitHub Actions でも PostgreSQL を起動し、両方を実行しています。テストの中身と実行方法は [docs/動かし方.md](docs/動かし方.md) にあります。

## 詰まったところ

- Azure の DB にマイグレーションを当てたとき、`28P01` が出ました。パスワードが3種類（Azure のアカウント・DB の管理ユーザー・手元の `.env`）あり、取り違えていました。
- Container App を作成したとき、`MANIFEST_UNKNOWN` が出ました。調べると、イメージのタグの誤りなどが原因として挙がっていたので、push し直して解決しました。
- 統合テストの接続先を `localhost` にしていたところ、2件で34秒ほどかかったり、タイムアウトしたりしました。Windows では先に IPv6（`::1`）へ接続しようとするのが原因で、`127.0.0.1` に変えると全件で1秒ほどになりました。

## 動かし方（手元）

Docker Desktop を起動してから、リポジトリの一番上のフォルダーで実行します。

1. `.env.example` をコピーして `.env` を作り、パスワードと仮の鍵を書き換えます（`.env` は git に入れません）。
2. DB のボリュームを作ります（初回のみ）: `docker volume create kakeibo-db-data`
3. API と DB を起動します: `docker compose up --build -d`
4. `ShopListApi/ShopListApi` のフォルダーで `dotnet ef database update` を実行し、表を作ります（接続先は `.env` の値に合わせます）。
5. `X-Api-Key` に `.env` の `API_KEY` を付けて `http://localhost:8080/categories` を呼ぶと 200、付けないと 401 が返ります。

初期分類の投入・テストの実行・Azure での手順は [docs/動かし方.md](docs/動かし方.md) にあります。
