# shop-list-api（家計の記録 API）

家計簿を毎回スマホで手で付けるのが面倒だったので、自動で記録できるようにした Web API です。
Apple Pay で払うと、金額と店名だけが送られて記録されます。分類（食費・交通費など）は、自分で決めた分類ルールで自動で決まります。
月ごと・分類ごとの集計も取れます。

> 作っている途中です（2026-10-22 時点）。分類の API ができ、いまは取引を作っています。進み具合は「[進み具合と今後](#進み具合と今後)」を見てください。

## 作った理由

- 家計簿アプリで記録するには、毎回アプリを開いて、分類を選び、金額を入れる必要があります。これが面倒で続きませんでした。
- 入力を「金額と店名」だけにして、分類は自動で決まるようにすれば、記録の手間をほぼなくせると考えました。
- 家計簿アプリはすでにたくさんあります。この作品では、次の2点を自分で決められるようにしました。
  - 分類のしかた: 「店名にこの言葉が入っていたらこの分類」というルールを自分で作れます。分類を手で直すと、次から同じ店はその分類になります。
  - 見せ方: 画面は持たない API だけの作りなので、記録したデータを好きな形で表示できます。

## 記録の流れ

```text
Apple Pay で払う
  → iPhone のショートカット（「取引」のオートメーション）が金額と店名を送る
  → API が分類ルールで分類を決めて保存する

現金などのとき
  → 同じ API に、手で金額と店名を送る
```

- 自動の記録も手の記録も、同じ登録の API を使います。どちらから来たかは `source`（`auto` / `manual`）で残します。
- ショートカットそのものは、この作品の範囲外です。

## できること

| 機能 | 内容 |
| --- | --- |
| 取引 | 支出と収入を記録する。金額と店名だけで登録でき、日付を省くと今日になる。一覧・1件の取得・更新・削除 |
| 分類 | 分類の一覧・登録・更新・削除。最初から「食費・日用品・交通費・趣味・固定費・給料」を用意する |
| 自動分類 | 店名と分類ルールから分類を決める。どのルールにも当たらなければ未分類（空）にする |
| 分類ルール | 「店名のキーワード → 分類」の一覧・登録・更新・削除 |
| 集計 | 月か期間を指定して、分類別の合計・支出の合計・収入の合計・残り（収入 − 支出）を返す |

画面（フロントエンド）は作りません。手元では `.http` ファイルなどから API を呼んで確かめます。

## 使っている技術

| 技術 | 選んだ理由 |
| --- | --- |
| C# / .NET 10 | 今の仕事で C# を使っていて、サーバー側でも使えるようにしたかったため |
| ASP.NET Core（コントローラー） | 業務ではコントローラーで書かれていることが多いと考えたため |
| Entity Framework Core | .NET で DB を扱う標準的な方法のため |
| PostgreSQL（手元は Docker） | Azure に縛られず、ほかのクラウドにも持っていけるため |
| Azure App Service（予定） | Microsoft の公式ドキュメント（Microsoft Learn）を読みながら、.NET と同じ会社のクラウドに載せるため |

## 設計で決めたこと

細かい内容は [docs/設計.md](docs/設計.md) にあります。ここでは主なものだけ書きます。

- **REST で、1回のリクエストで1つの操作をする。** まとめて送る API は作りません。今はまとめて送る場面がなく、作る手間に見合わないためです。
- **分類の決め方。** 店名の中にキーワードがそのまま入っていれば当たりとします。2つ以上のルールが当たったら、キーワードが長いほう（より詳しく一致したほう）を使います。
- **未分類は分類として持たない。** どのルールにも当たらない取引は分類を空（`null`）にして、「未分類」と表示するのはクライアントに任せます。こうすると、「消せない未分類」という特別な分類を守る処理がいらなくなります。
- **金額は円の整数で、いつもプラス。** 支出か収入かは `type`（`expense` / `income`）で表します。
- **エラーは Problem Details（RFC 9457）の形にそろえる。** アプリが決めたエラー（見つからない・ぶつかる など）には、種類を見分けるために `category.in_use` のような意味の分かる文字列のコードを付けます。入力の誤り（400）は、項目ごとの理由を `errors` で返します。
- **値の置き場所を2つに分ける。** 金額の範囲や文字数など DB の形に関わる値はコードの定数に、1ページの件数など運用しながら変えたい値は設定ファイル（`appsettings.json`）に置きます。
- **一覧の並び順は固定。** ページ分割したときに同じ行が2回出たり抜けたりしないように、最後は必ず id で並べます。

### API の一覧

| リソース | URL | 操作 |
| --- | --- | --- |
| 分類 | `/categories` | 一覧・1件・登録・更新・削除 |
| 取引 | `/transactions` | 一覧（分類・期間で絞れる。ページ分割）・1件・登録・更新・削除 |
| 分類ルール | `/category-rules` | 一覧（ページ分割）・1件・登録・更新・削除 |
| 集計 | `/summaries` | `?month=2026-10` か `?from=...&to=...` で月か期間の集計 |

送るもの・返すもの・エラーの一覧は [docs/設計.md](docs/設計.md) を見てください。
